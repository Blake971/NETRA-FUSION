# NETRA
# Project Overview

Version: 2.0

Status: Planning Phase

---

# 1. Introduction

NETRA is a web-based AI-powered cybersecurity platform that performs passive security assessments using publicly available information. The platform consolidates multiple security checks into a unified dashboard, calculates an overall security score, generates AI-powered explanations, and produces professional reports.

NETRA is **not** a penetration testing tool.

NETRA does **not** exploit vulnerabilities.

NETRA does **not** perform brute-force attacks.

NETRA only analyzes information intentionally exposed through public Internet infrastructure and standard networking protocols.

The primary objective is to help users understand their digital footprint, identify common security misconfigurations, and improve their cybersecurity posture.

---

# 2. Vision

To create a modern, intelligent, and user-friendly cybersecurity platform that simplifies security analysis by combining multiple publicly available information sources into one centralized dashboard.

NETRA should provide enterprise-quality insights while remaining easy enough for students, website owners, and beginners to understand.

---

# 3. Mission

Provide automated security assessment using only publicly available information.

Replace multiple individual tools with one intelligent dashboard.

Generate AI-powered explanations instead of only technical outputs.

Promote ethical and defensive cybersecurity practices.

# 9. Core Principles

Every module must work independently.

Every module returns JSON.

Frontend never talks directly to Internet services.

Frontend communicates only with FastAPI.

FastAPI communicates with scanner modules.

Scanner modules communicate with Internet resources.

AI never performs security analysis.

AI only explains findings.

Risk Score is generated by our own algorithm.

---

# 10. Coding Standards

Every module must have one responsibility.

Functions should remain small.

Avoid duplicate code.

Every function must return structured JSON.

Every API must return standard HTTP responses.

Handle all exceptions.

Never crash the application.

Log all module errors.

---

# 11. JSON Standard

Every scanner must return:

```json
{
    "module": "",
    "status": "",
    "severity": "",
    "message": "",
    "data": {}
}
```

Example:

```json
{
    "module":"SSL",
    "status":"PASS",
    "severity":"LOW",
    "message":"Certificate Valid",
    "data":{
        "issuer":"Let's Encrypt"
    }
}
```

---

# 12. Development Rules

Build vertically.

Never build all modules simultaneously.

Complete one feature end-to-end.

Example:

WHOIS → Backend → Frontend → Dashboard → Testing → Commit

Then begin DNS.
